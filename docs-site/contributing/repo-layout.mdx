AndySU is one monorepo. Every package is released under one version; the Host API level is a separate
integer that only goes up.

| Path | What |
|---|---|
| `spec/` | the protocol (`SPEC.md`), JSON Schemas, and manifest fixtures (valid and invalid) |
| `core/` | Rust, sans network IO: verify, select, patch, extract, slot state machine; C ABI and JNI. Has `tests/` and `fuzz/` |
| `cli/` | the `andysu` CLI: keygen, init, split, pack, publish, sign, rollback, verify, serve, and more |
| `desktop/` | a Linux desktop host in C that live-swaps a `.so` payload |
| `android/` | `api`, `host` (the AAR), `payload-kit`, `gradle-plugin`, `host-template`, `testapp`, `samples`, and `tests` (device tests) |
| `bindings/` | React Native and Expo, Capacitor, Flutter, Unity, Godot, C and CMake |
| `actions/publish` | the GitHub Action that publishes payloads |
| `templates/remote` | a GitHub template for an app's update remote (Pages-served channels, promotion, rollback) |
| `testbeds/patches/` | patches that make Xonotic Touch and SuperTuxKart Touch defer to AndySU |
| `testbeds/` (other) | shallow clones of other projects, git-ignored |
| `scripts/` | env, version, packaging, registries, secrets, demo channel, consumer verification |
| `docs/` | `BRIEF.md`, `DECISIONS.md`, `PROGRESS.md`, `KEYS.md`, `REGISTRIES.md`, `THREAT_MODEL.md`, `evidence/` |
| `docs-site/` | this documentation site (Mintlify) |
| `keys/` | the public root key for release verification; the old CI test key stays for historical releases |
| `Formula/` | the Homebrew formula, regenerated by each release |
| `.github/workflows/` | `ci.yml` (tests) and `release.yml` (release) |

## Core design rules

- **The core is sans-network-IO.** It never opens a socket. Hosts fetch bytes and write downloads to the
  paths the core names. It does touch the filesystem, because atomic state writes, staging and
  extraction must be crash-safe and identical everywhere. An optional `transport` feature adds a
  blocking HTTP client for C hosts and the CLI.
- **The API is Java with platform types only** (`android/api`), so a host built years ago still works
  with new payloads.
- **Versions** are `<major.minor>.<commits on main>` (`VERSION` holds `0.1`), computed by
  `scripts/version.sh`.

## Editing this site

The site is MDX in `docs-site/`, configured by `docs-site/docs.json`. Mintlify's GitHub integration
deploys it from `main` (monorepo path `docs-site`). To preview locally:

```sh
cd docs-site
npx mint dev            # http://localhost:3000
npx mint broken-links   # check internal links
npx mint validate       # check docs.json and the build
```

A change that touches only `docs-site/` does not run CI and does not make a release, see
[PR flow](/contributing/pr-flow#docs-only-changes). Keep every command, flag, key and event name in
sync with the code: the sources are `cli/src`, `android/host/src`, `spec/` and `docs/`.
