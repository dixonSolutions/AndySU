title: "Package registries"
description: "Install every AndySU package from the project's own GitHub remote."
---

AndySU's default packages are published to this repository's own GitHub remote, not to public
registries:

- **GitHub Pages** (`https://dixonsolutions.github.io/AndySU`) serves static registries: `maven/`,
  `npm/`, `cargo/` and `pub/`. The release workflow keeps them on the `gh-pages` branch.
- **GitHub Releases** (`v<version>`) carry the same packages as files, plus CLI binaries, the C and
  Godot archives, the host template and `SHA256SUMS` with a detached signature.

Versions are `<major.minor>.<commits on main>` (for example `0.1.78`). The latest release and its
Pages indexes were checked on 2026-11-04; use the newest version on the
[releases page](https://github.com/dixonSolutions/AndySU/releases). GitHub Packages is not used,
because it needs a token even to install public packages.

| Ecosystem | Package | How | Verified |
|---|---|---|---|
| Gradle | `io.github.dixonsolutions.andysu` | static Maven repo with plugin marker | CI consumer install; 0.1.78 artifacts live |
| Cargo | `andysu-core`, `andysu-cli` | sparse registry | CI consumer install; 0.1.78 indexes live |
| npm | `@andysu/react-native`, `@andysu/capacitor`, `@andysu/cli` | static packuments, scoped registry | CI consumer install; 0.1.78 packuments live |
| Unity | `com.andysu.unity` | npm protocol as a scoped registry | CI checks the exchange; Unity itself needs a licence |
| pub | `andysu` | Hosted Pub Repository v2, static | CI consumer install; 0.1.78 index live |
| C and CMake | `andysu-c-<v>-linux-<arch>.tar.gz` | release asset | CI consumer install |
| Godot | `andysu-godot-<v>.zip` | release asset | CI consumer install |
| Homebrew | `andysu` CLI | tap = the repository (`Formula/`) | CI consumer install (Linux and macOS) |
| GitHub Action | `dixonSolutions/AndySU/actions/publish` | subdirectory action | action smoke test in CI |

## Cargo

`.cargo/config.toml`:

```toml
[registries.andysu]
index = "sparse+https://dixonsolutions.github.io/AndySU/cargo/"
```

```sh
cargo install andysu-cli --registry andysu
```

```toml
[dependencies]
andysu-core = { version = "0.1", registry = "andysu" }
```

## npm

```ini
@andysu:registry=https://dixonsolutions.github.io/AndySU/npm/
```

```sh
npx @andysu/cli --version     # the CLI, bundled for Linux and macOS (x64, arm64)
```

Only the `@andysu` scope goes to this registry; everything else still comes from npmjs.com. When
the optional public npmjs.com publishing is enabled, the same packages are published there under
unscoped names: `andysu` (the CLI), `andysu-react-native`, `andysu-capacitor` and
`com.andysu.unity`. Release tarballs also work:
`npm install https://github.com/dixonSolutions/AndySU/releases/download/v0.1.78/andysu-react-native-0.1.78.tgz`.

## Homebrew

```sh
brew tap dixonsolutions/andysu https://github.com/dixonSolutions/AndySU
brew install dixonsolutions/andysu/andysu
```

The release workflow regenerates `Formula/andysu.rb` on `main` with a `[skip ci]` commit.

## Optional public registries

The crates.io and npmjs.com jobs use trusted publishing through GitHub OIDC. They remain disabled
unless `PUBLISH_CRATES_IO=true` or `PUBLISH_NPMJS=true` is set as a repository variable after each
package has its trusted publisher configured. They do not require long-lived registry write tokens.
See [Keys policy](/contributing/keys-policy) for initial publication and setup. These optional jobs
do not change the GitHub Pages and Releases installation instructions above.
